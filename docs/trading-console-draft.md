# 설계 초안 — 트레이딩 콘솔 화면 반영 (러프)

참고 이미지(DataLumen "시스템 예시")의 5개 블록을 MyStock 기존 구조 위에 얹는 초안.
**위치 + 같이 놓을 데이터**만 적는다. 세부 UI·API 스펙은 다음 단계.

> 전제: MyStock은 시그널·계좌 관리 앱이고 자동매매(주문 실행)는 범위 밖.
> 이미지의 "봇"은 **시그널 프리셋(전략)** 으로, "주문"은 **체결 기록(trades)** 으로 치환한다.

---

## 한눈에 보기 — 블록 → 위치 매핑

| 이미지 블록 | 놓을 위치 | 신규/확장 | 핵심 데이터 소스 |
|---|---|---|---|
| ① 차트 + 지표 토글 | `/ticker/:symbol` 상단 | 확장 | `price_cache`, `indicators.py` |
| ② 계좌 잔고 패널 | `/` 대시보드 우측 상단 + `/portfolio` 헤더 | 확장 | `/portfolio`, `broker_holdings`, `meta(cash)` |
| ③ 종목 필터링 | `/watchlist` → 스크리너 모드 | 확장 | `signal_history`, `tickers`, 스코어 요소 |
| ④ 주문·매도 이력 | `/portfolio/journal` (매매 기록) | 확장 | `trades`, `cash_flows`, `broker_holdings` |
| ⑤ 봇(전략) 설정 | `/portfolio/settings` → 새 탭 `/portfolio/strategy` | 신규 | `custom_rules`, `meta`, 신규 `strategy_presets` |

---

## ① 종목 상세 — 차트 + 지표 레이어 (`/ticker/:symbol`)

**위치**: 종목명 헤더 바로 아래, 백테스트 표 위. 화면 폭 전체.

**구성**
- 상단 바: `심볼 · 거래소 · 주기(일봉)` / 우측 `다음 갱신까지 카운트다운` (1시간 갱신 주기 활용, `last_refresh` 기반)
- 프리셋 탭: `스윙 | 중장기 | 내 설정` — 탭마다 켜진 지표 세트가 다름 (⑤에서 정의한 프리셋과 연결)
- 지표 체크박스 행: 현재 `indicators.py`가 이미 계산하는 것부터
  - 메인 패널: MA(20/50/200), 볼린저(상·중·하), ATR 손절선(`atr_stop_price`), 매수/매도 마커(`trades`), 시그널 등급 변경 지점(`signal_history`)
  - 서브 패널: 거래량(+평균), RSI, MACD(히스토그램), 나중에 MFI/WT
- 우측 가격축 라벨: 현재가, 평단가(보유 시), 손절가, 목표가(`custom_rules`)

**데이터**: `/tickers/{symbol}` 응답에 OHLCV 배열 + 지표 시계열 추가. 지금은 최신값만 내려주므로 시계열 필드 확장 필요.

**이미지와 다른 점**: 봇 1·2·3 대신 시그널 프리셋. 차트 라이브러리(lightweight-charts 등)는 별도 결정.

---

## ② 계좌 잔고 패널 (`/` 대시보드 우측 상단, `/portfolio` 공통 헤더)

**위치**
- 대시보드: 오른쪽 1/3 컬럼 고정 카드 (모바일에선 맨 위)
- 포트폴리오: 6개 탭 위에 얇은 공통 헤더로 축약판

**구성**
- 계좌 선택: `전체 | 국내(증권사 계좌) | 해외 | 직접입력` — `broker_holdings.account` + 수기 trades 구분
- 우측 버튼: `동기화`(`POST /broker/sync`) + `마지막 싱크 시각` (`/broker/status`)
- 숫자 4칸:
  - 주문 가능액 = 예수금(`meta.cash` 또는 CODEF 잔고)
  - 매수 총액 = Σ(수량×평단)
  - 총 손익 = 평가손익 + 실현손익(`/portfolio` 기존 계산)
  - 총 수익률 (%) — 원화 환산 기준, `fx_rate` 반영
- 하단 보유 테이블(축약): `전략 태그 | 심볼 | 상태 | 수량 | 평단`
  - 상태 = `보유 / 손절 근접 / 목표 근접 / 트레일링` — `custom_rules` 도달 거리로 계산
  - 전략 태그 = 진입 시 시그널 등급 스냅샷 또는 ⑤ 프리셋명

**데이터**: 모두 기존 `/portfolio`, `/broker/*` 응답으로 가능. 새로 필요한 건 "상태" 파생 필드 하나.

## ③ 종목 필터링 / 스크리너 (`/watchlist` 확장)

**위치**: 워치리스트 페이지 상단에 필터 바 추가, 아래 표는 기존 워치리스트 표를 재사용. 토글로 `내 워치리스트 | 전체 스크리닝` 전환.

**구성**
- 1행: `프리셋 선택`(⑤ 연동) / `기준일`(`signal_history` 날짜) / `필터 실행`
- 2행 정렬 탭: `전체(n) | 거래대금순 | 점수순 | 매수 신호만`
- 3행 조건 칩 (토글식, 켜진 것만 AND):
  - 추세: `정배열`, `MA20>MA50`, `MA200 위`, `신고가 근접`
  - 모멘텀/과매도: `RSI<30`, `RSI 상향 돌파`, `MACD 골든`, `BB 하단 터치`
  - 점수: `스윙 A 이상`, `중장기 A 이상`, `등급 상향 전환`
  - 시장: `KR | US | CRYPTO | ETF`
- 결과 표 컬럼: `# | 종목 | 거래소 | 스윙등급 | 중장기등급 | 점수 | RSI | 거래대금 | 추세국면 | 근거(1줄)`
  - 이미지의 분기/연간 EPS 칸은 펀더멘털 데이터가 없으므로 **보류** (나중에 fetcher 추가 시 컬럼만 열어둠)

**데이터**: `signal_history` + 최신 지표값. 필터 조건은 쿼리 파라미터로 `GET /screen?conds=...` 신규 엔드포인트 하나.

**주의**: "전체 스크리닝"은 유니버스가 필요. 1차는 워치리스트+보유종목만, 2차에 시장 유니버스(KOSPI200, S&P500 구성종목) 캐시.

---

## ④ 주문·매도 이력 (`/portfolio/journal` 매매 기록 확장)

**위치**: 기존 매매 기록 탭을 상/하 2단으로 나눔.

**상단 — 체결 이력 (`trades`)**
- 필터 바: `계좌/전략 | 시장 | 기간(시작~끝) | 조회` + 우측 `총 n건`
- 컬럼: `전략태그 | 종목 | 거래소 | 수량 | 체결가 | 상태(체결/CODEF 가져옴/수기) | 날짜 | 메모`
- 행 클릭 → 기존 TradeDialog로 메모·시그널 스냅샷 편집

**하단 — 청산(매도) 이력 (`trades` 중 SELL + 매칭된 BUY)**
- 컬럼: `전략태그 | 종목 | 수량 | 진입가 | 매도가 | 사유 | 날짜 | 손익(R 배수)`
- 사유 = `손절 / 목표가 / 트레일링 / 분할매도 / 수동` — 매도 시점에 어떤 `custom_rules`가 도달 상태였는지로 자동 추정, 수동 수정 가능
- 이 사유 컬럼이 `/portfolio/realized`(복기)의 "진입 등급별 성과"와 짝을 이룸 → 복기 탭에 `사유별 손익` 한 줄 추가

**데이터**: `trades`에 `exit_reason` 컬럼 1개 추가. 나머지 기존.

---

## ⑤ 전략(봇) 설정 (`/portfolio/strategy` 신규 탭)

**위치**: 포트폴리오 탭에 `전략` 추가 (설정 탭 왼쪽). 기존 `설정` 탭의 `목표 종목 수`·`알림`은 그대로 두고, 리스크 파라미터만 이쪽으로 이동.

**레이아웃**: 좌측 프리셋 목록 / 우측 선택된 프리셋 편집 폼 / 맨 아래 변경 이력.

**좌측 — 프리셋 목록**
- `국내 스윙`, `해외 ETF`, `중장기` … 사용자 정의 N개
- 각 프리셋이 ①의 차트 탭, ③의 필터 프리셋, ②의 전략 태그로 공유됨

**우측 — 편집 폼 (카드 단위)**
- 진입 조건 카드: 조건식 1줄 요약(`MA20 > MA50 AND RSI < 40` 식) + 단기/장기 MA 길이, 최소 등급
- 손절 카드: `고정 손절 %` / `ATR 배수(기본 2)` / `분할매도 수량 %` — 현재 `position-rule`의 1% 리스크와 연결
- 트레일링 스탑 카드: `트리거 %` / `스탑 %` — 도달 시 ②의 상태가 "트레일링"으로 바뀌고 텔레그램 발송
- 분할매도 카드: `MA 길이` / `ATR 길이` / `매수 분할 수(k)` / `분할매도 수량 %`
- 저장 → `custom_rules`에 해당 프리셋 태그 달린 룰 자동 생성/갱신

**하단 — 변경 이력**
- `날짜 | 프리셋 | 바뀐 항목 | 이전→이후 | 상태(적용/되돌림)` — 복기 시 "그때 손절 폭이 몇이었나"를 확인하는 용도

**데이터**: 신규 테이블 `strategy_presets(id, name, params_json, created_at)` + `strategy_changes(preset_id, diff_json, changed_at)`. 룰은 기존 `custom_rules`에 `preset_id` 외래키 추가.

---

## 반영 순서 제안 (의존성 기준)

1. **⑤ 프리셋 테이블** — 나머지 4개 블록이 참조하는 공통 키. 먼저 최소 스키마만.
2. **② 잔고 패널** — 기존 API로 거의 끝남, 체감 큰 변화.
3. **④ 이력 2단 + exit_reason** — 컬럼 1개 추가, 복기 탭과 연결.
4. **① 차트** — 시계열 API 확장 + 차트 라이브러리 도입. 작업량 최대.
5. **③ 스크리너** — 유니버스 확보가 선행돼야 해서 마지막.

## 의도적으로 빼는 것
- 실제 주문 전송(자동매매) — 서비스 범위 밖, 법적·안전 이슈.
- EPS 등 펀더멘털 컬럼 — 데이터 소스 없음, 컬럼 자리만 예약.
- 모의투자 계좌 분리 — 필요해지면 `broker_holdings.account`에 가상 계좌 하나 추가하는 방식으로.

# 화면 기준 배치 (와이어프레임)

공통: 상단 네비 `대시보드 | 포트폴리오 | 워치리스트` 는 그대로. 데스크톱 기준이며 모바일은 각 화면 맨 아래에 적은 순서로 세로 적층.

## A. 대시보드 `/`


## D. 포트폴리오 공통 헤더 + 매매 기록 `/portfolio/journal`
