# 횡단면 모멘텀 프리셋 — 설계

2026-08-26. 승인된 설계. `2026-08-26-strategy-validation-design.md`(측정 인프라)와
검증/실행 정합성 작업의 후속 — **측정할 자가 생겼으니 이제 알파를 찾는다.**

## 왜 이 전략인가 (실측 근거)

`_workspace/strategy-validation/baseline.md`의 워크포워드 실측이 이 설계의 전제다.

| 구성 | 초과수익 중앙값 | 이긴 폴드 | 연결 CAGR | 연결 MDD |
|---|---|---|---|---|
| krx300 · 절대모멘텀 | -16.3%p | 0/5 | -13.9% | -56.5% |
| krx300 · 돈치안 | -7.7%p | 2/5 | -4.1% | -50.4% |
| krx300 · 절대모멘텀 + 레짐 | +2.5%p | 3/5 | +7.2% | -28.3% |
| krx300 · 돈치안 + 레짐 | **+4.6%p** | 3/5 | +7.2% | -31.9% |

현 프리셋 두 개는 **둘 다 시계열(절대) 모멘텀 계열**이다. 자기 과거 수익률의
부호만 보고, 유니버스 안에서 상대적으로 무엇이 강한지는 보지 않는다. 실측에서
드러난 구조적 약점이 정확히 여기서 나온다:

> 레짐 필터 개선의 큰 몫은 2022년 하락장 폴드에서 "거래 0으로 회피"(+22.0%p)가
> 차지하고, 지수 급등 폴드(F5, KOSPI 연환산 +113%)에서는 **-112%p로 크게
> 뒤처진다** — 추세추종 선별이 지수 랠리를 못 따라가는 구조적 특성.

절대 게이트(`모멘텀 > 0 AND 종가 > 추세선`)는 랠리에서 **너무 늦게, 너무 적게**
진입한다. 상대 랭킹은 "지금 유니버스에서 가장 강한 것"을 항상 보유하므로 이
구멍을 겨냥한다. F5의 -112%p가 개선되지 않으면 이 전략은 기각이다.

## 지금 구조가 막고 있는 것

`engine.run`은 **이미 매일 진입 후보를 `strength` 내림차순으로 정렬해 7자리로
자른다.** 즉 "선별"은 이미 횡단면이다. 절대적인 것은 **진입 게이트**다.

따라서 이 작업의 실질은 "랭킹 기능 추가"가 아니라 **게이트를 절대 기준에서
상대 기준으로 바꾸는 것**이다. 문제는 계약이다 — `strategy.py`의 프리셋은
`fn(df, params)`, 즉 "종목 하나의 일봉 → 신호"인 순수 함수다. 상대 랭킹은
유니버스 전체를 봐야 계산된다.

### 검토한 접근법

| 안 | 내용 | 판정 |
|---|---|---|
| **A** | `PRESETS`에 `kind` 태그, 횡단면은 `universe_fn(frames, params, eligible)` 노출. engine이 선언된 쪽을 부르고 그 뒤 자료구조는 불변 | **채택** |
| B | 전 프리셋을 `fn(frames, params)` 유니버스 계약으로 통일 | 기각 — 종목 단위 순수성(단위 테스트가 쉬운 이유)을 잃고 autotrade·테스트·골든을 기능 이득 없이 건드린다 |
| C | 프리셋은 `strength`만 주고 engine이 상위 K% 마스크를 얹는다 | 기각 — 청산도 랭킹 기반이어야 하는데 청산은 종목별 `exit` 배열을 앞으로 스캔해 해결하는 구조라 결국 종목별 배열로 재료화해야 하고, 그러면 C의 이점이 사라진다. 게다가 "무엇의 상위 K%인가"는 전략의 결정인데 그 답이 engine에 숨는다 |

A를 택하는 이유: "언제 사고 파는가"는 `strategy.py` 한 곳에 남고, engine의
검증된 벡터화 내부 루프(골든 픽스처가 지키는)는 손대지 않는다.

## ① 시그널 계약

```python
TIMESERIES = "timeseries"
CROSS_SECTIONAL = "cross_sectional"

def xs_momentum(frames: dict[str, pd.DataFrame], params: dict,
                eligible: dict[str, pd.Series] | None = None
                ) -> dict[str, pd.DataFrame]:
    """유니버스 내 모멘텀 상대 랭킹. 각 종목 자기 인덱스에 정렬된 신호를 돌려준다."""
```

`PRESETS["xs_momentum"]`은 `fn` 대신 `universe_fn`과 `"kind": CROSS_SECTIONAL`을
갖는다. 기존 두 프리셋에 `"kind": TIMESERIES`를 **명시**한다 — 기본값에
의존하면 새 프리셋에서 태그를 빼먹은 것이 조용히 지나간다.

`engine.run`의 변경은 준비 루프 한 곳이다. 순서만 바꾼다:

```
① 정리:  cleaned[sym] = df.dropna(subset=OHLC)      # 지금 로직 그대로
② 시그널: kind == CROSS_SECTIONAL
            → sigs = universe_fn(cleaned, params, eligible)
          아니면
            → sigs = {sym: fn(df, params) for sym, df in cleaned.items()}
③ 이후:  prepared[sym]["sig"] = sigs[sym]            # 여기부터 한 줄도 안 바뀜
```

**정리된 프레임을 넘기는 것이 계약의 핵심이다.** engine은 `sig` 컬럼을
`.to_numpy()`로 펼쳐 `df.index` 위치로 색인하므로, 신호가 `cleaned[sym].index`와
정확히 같은 길이·순서여야 한다. 원본 프레임으로 랭킹하면 거래정지 행이 하나
들어갈 때마다 신호가 한 칸씩 밀린다 — 그리고 그 오류는 예외를 던지지 않고
조용히 틀린 자본곡선을 만든다. `sigs`에 없는 종목은 "신호 없음"으로 건너뛴다.

`eligible`은 `{sym: bool Series}`로, `membership`이 있으면 그것을, 없으면 전부
True를 engine이 만들어 넘긴다. engine이 `enter_mat`에 멤버십 마스크를 다시
얹는 현재 코드는 **그대로 둔다** — 멱등이고, 시계열 프리셋에는 여전히 그
마스크가 유일한 방어선이다.

## ② 랭킹·룩어헤드 규칙

점수는 기존 `momentum(close, lookback, skip)`을 그대로 쓴다 — 이미 `.shift(skip)`
으로 룩어헤드가 막혀 있고, 새 지표를 만들면 그 방어를 처음부터 다시 증명해야
한다.

```
① 전 종목 close를 공통 달력에 outer-join → wide DataFrame
② 모멘텀 계산 (열 단위, 기존 함수)
③ eligible=False인 칸을 NaN으로 지운다        ← 분모가 결정되는 지점
④ rank(axis=1, pct=True, ascending=False)     ← 같은 날 횡단면만 본다
⑤ 종목별로 자기 인덱스에 reindex
```

③이 이 설계에서 가장 중요한 한 줄이다. pandas의 `rank(pct=True)`는 그 행의
**non-NaN 개수로 정규화**하므로, NaN으로 지우면 분모가 자동으로 "그날 유효한
종목 수"가 된다. 상장 전·거래정지·폐지 후·멤버십 이탈이 전부 같은 방식으로
빠진다. NaN을 최하위 순위로 채우면 분모가 부풀어 "상위 20%"가 실제로는 상위
30%가 된다.

| | 규칙 |
|---|---|
| 진입 | `rank_pct <= enter_pct/100` |
| 청산 | `rank_pct > exit_pct/100` **또는 `rank_pct`가 NaN** |
| strength | 모멘텀 원값 |

**NaN을 청산 신호로 보는 이유**: 랭킹을 계산할 수 없게 된 종목(거래정지·폐지
임박)을 계속 보유할 근거가 없다. False로 두면 그 종목은 손절이나 데이터
끝까지 절대 안 팔린다. 워밍업 구간에도 `exit=True`가 깔리지만, 진입은 non-NaN
날에만 일어나므로 없는 포지션의 청산 신호는 무해하다.

**strength를 랭킹이 아니라 모멘텀 원값으로 두는 이유**: 같은 날 안에서 두 값의
정렬 순서가 동일하고(단조 변환), 원값이면 다른 프리셋과 비교 가능한 채로
남는다. engine의 자리 자르기 결과는 어느 쪽이든 같다.

세 컬럼 모두 기존 두 프리셋과 같은 관례로 결측을 확정한다 — `enter`·`exit`는
`fillna(False).astype(bool)`, `strength`는 `fillna(0.0).astype(float)`. 결측을
남기면 engine이 NaN을 참으로 읽을 여지가 생긴다.

`enter_pct < exit_pct`는 검증한다 — 같거나 뒤집히면 히스테리시스가 사라져
경계에서 매일 들락날락하며 비용만 먹는다.

### 룩어헤드 감사 (5개 지점, 전부 이 설계에서 닫힘)

1. 랭킹은 같은 날 횡단면만 — 미래 날짜가 안 들어간다
2. 모멘텀은 `.shift(skip)` 유지
3. 진입은 여전히 신호 익일 시가 (engine 불변)
4. 워크포워드가 `frames`를 폴드별로 절단한 뒤 `run()`을 부르므로, 랭킹이 다음
   폴드 가격을 못 본다
5. 폐지 종목은 마지막 봉 이후 wide 프레임에서 NaN → 분모에서 자동 제외.
   생존편향이 랭킹으로 새지 않는다

## ③ 파라미터 그리드

`strategy.py`의 기존 상한(조합 12~15개)을 지킨다. 워크포워드는
`폴드 × (조합+1)`회 `run()`을 돌리므로, 조합이 24개면 964종목에서 실행시간이
두 배가 되고 우연히 검증 구간까지 맞는 조합이 나올 확률(다중비교
오버피팅)도 함께 오른다.

| 파라미터 | 기본 | min~max | 그리드 | 근거 |
|---|---|---|---|---|
| `lookback` | 252 | 20~504 | `[126, 252]` | 6개월·12개월 — 모멘텀 문헌의 두 표준 |
| `skip` | 21 | 0~63 | `[21]` (탐색 안 함) | 12-1의 표준값. 그리드에 넣으면 조합이 2배인데 이 구간에서 재탐색할 근거가 약하다 |
| `enter_pct` | 20 | 1~50 | `[10, 20, 30]` | 진입 후보 풀 크기 |
| `exit_pct` | 50 | 5~100 | `[40, 60]` | 히스테리시스 폭 |

min~max는 화면 입력 상한이며 기존 두 프리셋과 같은 형식(`min`/`max`/`label`/
`grid`)으로 `PRESETS`에 담는다.

**12조합.** 모든 조합이 `enter_pct < exit_pct`를 만족한다(최대 30 < 최소 40).

### 미리 밝히는 한계

**`enter_pct`의 실질 효과는 `MAX_POSITIONS = 7`에 상당 부분 가려진다.** krx300
멤버십이 300종목이면 상위 10%도 30종목인데 자리는 7개뿐이라, 후보 풀을 10%로
좁혀도 실제 보유는 여전히 strength 상위 7종목이다. 풀 크기가 실제로 작동하는
건 "자리가 비었는데 후보가 없는" 경우뿐이다.

회전율을 지배하는 건 `exit_pct`일 가능성이 높다. 워크포워드에서 `enter_pct`가
폴드마다 튄다면 그건 이 구조 때문이며, **파라미터가 무의미하다는 증거로 읽어야
한다** — 우연히 좋았던 값을 채택하는 근거가 아니다.

### 자동매매는 연구실 전용으로 막는다 (결정)

관심종목 18종목에서 상위 20%는 3.6종목이다. **상대 랭킹은 모집단이 바뀌면
다른 지표**이므로, 직접 고른 18종목 사이의 상위 20%는 krx300 상위 20%와 전혀
다른 물건이다. 직전 작업에서 닫은 "검증한 전략 = 실행하는 전략"을 다시 깨지
않는다. 효과가 입증되면 승격은 별도 결정으로 한다.

### 작은 유니버스 경고

`service`가 횡단면 프리셋을 돌릴 때, **`run()`이 실제로 신호를 만든 종목 수**
(`universe_size`, 30봉 미만 종목이 걸러진 뒤의 값)가 50 미만이면 응답 warnings에
"유니버스가 N종목이라 상대 랭킹의 의미가 약하다"를 싣는다. 수집한 종목 수가
아니라 실제 랭킹 분모 쪽을 세는 것이 이 경고의 취지다. 자동매매의 유니버스
불일치 고지와 같은 방식이다 — 수치 옆에 한계가 없으면 그 수치를 근거로 읽게
된다.

## ⑤ 검증 계획

### 단위 (TDD — 실패 확인 후 구현)

`test_strategy.py`
- 상위 K%만 진입하고, 분모가 그날 유효 종목 수다
- **`eligible=False`인 종목이 분모에서 빠진다** — 10종목 중 5개가 비적격이면
  상위 20%는 **1종목**(2종목이 아니다). ②의 핵심 방어선
- 모멘텀이 NaN인 종목은 진입 후보가 아니고, 보유 중이면 청산 신호가 뜬다
- `enter_pct >= exit_pct`면 `ValueError`
- 각 종목 신호가 자기 인덱스에 정렬된다(길이·인덱스 동일)
- **룩어헤드**: 프레임 뒤쪽을 잘라내고 다시 계산해도 마지막 날 신호가 같다

`test_engine.py` + 골든
- 횡단면 프리셋으로 `run()`이 자본곡선을 낸다
- 거래정지(NaN 행)가 섞인 종목에서 신호 정렬이 밀리지 않는다
- **골든 픽스처 재생성 금지.** 기존 두 프리셋 결과가 비트 단위로 같아야 한다 —
  준비 루프를 건드리는 이 작업에서 그게 유일한 안전망이다

소비자
- `save_settings`의 횡단면 거부, `settings()` 폴백
- `/strategy/presets`가 `kind`·`autotrade_capable`을 싣는다

### 실측 판정

`POST /api/strategy/walkforward` (universe=krx300), 레짐 ON/OFF 각각으로
`xs_momentum`을 돌려 `baseline.md`의 기존 4행과 같은 표에 추가한다. 특히
**F5(지수 연환산 +113% 폴드)에서 -112%p가 개선되는지**가 이 전략을 만든
이유다.

### 판정 기준 (사전 확정)

사후에 기준을 고르면 다시 노이즈를 고른다.

> **채택**: 초과수익 중앙값 > +4.6%p(현 최고: 돈치안+레짐) **AND** 이긴 폴드
> ≥ 3/5 **AND** 파라미터 안정성이 "불안정"이 아님
> **기각**: 그 외. 기각도 결과이므로 `baseline.md`에 같은 형식으로 남긴다

자동매매 기본값은 이 판정과 무관하게 건드리지 않는다.
