## 3. 치명적 결함 (Blocker)

### B1. 백테스트 로딩 중 "표본 부족 — 판단 근거로 쓰기에 관측이 부족합니다"가 뜬다

- **증상**: `backtest`는 `null`로 시작하고(`TickerDetail.tsx:83,96`) 상세와 **별도 요청**으로 뒤늦게 도착한다(`:99-100`). `gradeStat = backtest?.grades.find(...) ?? null` 이므로(`:119`) 응답 전에는 항상 null이고, 행동 요약 카드는 그 상태에서 `"표본 부족 — 이 등급은 판단 근거로 쓰기에 관측이 부족합니다"`를 렌더한다(`:228-233`).
- **근거**: `frontend/src/pages/TickerDetail.tsx:83, 96-101, 119, 228-233`
- **사용자 영향**: "지금 뭘 해야 하나"에 답하는 유일한 통계 근거 칸이, 근거가 **없다는 단정문**으로 먼저 보인다. 30초 판단자는 그 문장을 읽고 스크롤을 멈추거나 관망으로 기운다. 데이터는 곧 도착하지만 판단은 이미 끝났다. `backtest` 카드 자체도 로딩 자리표시가 없어(`:303-328`) "이 종목엔 백테스트가 없구나"로 읽힌다.
- **수정 방향**: `btLoading` 상태를 도입해 3분기(로딩 / 표본 부족 / 수치)로 분리한다. 로딩 중에는 `.skeleton` 자리표시 + "과거 성적 확인 중…". 백테스트 카드도 로딩 스켈레톤을 낸다. 근본적으로는 `/api/tickers/{symbol}`이 요약 통계(등급별 win/episodes)만이라도 함께 실어 첫 페인트에서 확정시키는 편이 낫다.

### B2. 예수금 초과 매수가 조용히 잘리고 사용자는 모른다 — 이후 모든 사이징이 오염

- **증상**: 백엔드는 매수 시 예수금이 음수로 가면 0으로 클램프하고, 그 사실을 `{"clamped": true, "applied": ...}`로 응답에 실어 보낸다(`backend/app/service.py:157-163`). 프론트는 `await post('/api/trades', ...)`의 반환값을 **전혀 읽지 않는다**(`TradeDialog.tsx:47-51`, `Portfolio.tsx:119-125`). `grep clamped frontend/` → 0건.
- **근거**: `backend/app/service.py:157-163`, `backend/app/api.py:128-131`, `frontend/src/components/TradeDialog.tsx:47-51`, `frontend/src/pages/Portfolio.tsx:119-125`
- **사용자 영향**: 매도는 보유 초과를 400으로 막는데(`api.py:113-116`) 매수는 막지 않는다. 예수금 200만 원인 계좌에 500만 원 매수를 기록하면 예수금이 0이 되고 **300만 원이 장부에서 증발**한다. 총자산이 실제보다 작아지고, 총자산을 분모로 쓰는 1% 리스크 수량(`service.py:418-421`)이 전 종목에서 과소 계산된다. 1차 리뷰의 B1(예수금 0 초기화)과 **정확히 같은 손상이 다른 경로로 재발**한다.
- **수정 방향**: (1) TradeDialog에 현재 예수금과 `수량 × 단가 + 추정비용 = 체결금액`을 실시간 표시하고 초과 시 진행 전 경고. (2) 저장 응답의 `clamped`를 받아 "예수금이 부족해 0으로 처리했습니다 — 입금 기록을 먼저 남기세요"를 토스트로 노출. (3) 성공 시에도 "예수금 ₩X → ₩Y" 변화를 1줄로 확인시킨다.

### B3. 매도·보유 판단을 지원하는 화면이 없다 (진입 편향)

- **증상**: TickerDetail 행동 요약의 5블록은 전부 신규 진입용이다 — 제안 손절가, 제안 목표가, **제안 수량(1% 리스크)**, 과거 성적, 손절 룰 등록(`TickerDetail.tsx:192-239`). 보유 사실은 `held_quantity`로 들어오지만 쓰이는 곳은 "추가 매수 가능 수량" 한 줄뿐이다(`:220-222`). 보유 중일 때 필요한 것 — 평단, 현재 수익률, 손절가까지 남은 거리, 목표가 도달 여부, 분할 청산 제안 — 은 이 카드에 하나도 없다. TradeDialog는 보유 여부와 무관하게 `side` 기본값이 `'BUY'`다(`TradeDialog.tsx:16`). 대시보드도 평단 대비 %는 주지만(`Dashboard.tsx:202-206`) 손절가 대비 위치는 없다.
- **근거**: `frontend/src/pages/TickerDetail.tsx:192-239`, `:220-222`, `frontend/src/components/TradeDialog.tsx:16`, `frontend/src/pages/Dashboard.tsx:202-206`
- **사용자 영향**: 개인 투자자의 손실 대부분은 진입이 아니라 청산에서 난다. 이 앱은 "얼마나 살까"에는 숫자로 답하고 "언제 팔까"에는 룰 알림이 터진 뒤에야 답한다. 손절가 -5%인 종목이 현재 -4.7%여도 화면 어디에도 경고가 없다 — `check_rules`가 **도달해야** 알림을 만들기 때문이다(`service.py:179`). 사용자는 임박 사실을 모른 채 다음 날 갭 하락을 맞는다.
- **수정 방향**: 보유 종목일 때 행동 요약 카드를 **청산 모드**로 전환한다. 블록 구성: 평단·현재 수익률 / 등록 손절가까지 남은 거리(%·₩) / 목표가까지 남은 거리 / 이 등급의 과거 20일 성적 / "일부 청산 기록" 버튼(side=SELL 프리필). 대시보드 보유 행에는 `손절까지 -1.2%` 형태의 잔여거리 컬럼을 추가하고, 잔여 2% 이내면 amber 표시한다.

### B4. Watchlist의 검색·추가 실패가 완전히 무음이다

- **증상**: `search()`는 `try/finally`만 있고 catch가 없다(`Watchlist.tsx:21-26`). `add()`도 `finally { setAdding(null) }`뿐이다(`:28-36`). 실패하면 unhandled rejection이 나고 화면은 아무 변화가 없다 — 결과 목록은 그대로, 추가 버튼은 다시 "+ 추가"로 돌아온다. 같은 앱의 CommandPalette는 `검색 실패 — 네트워크를 확인하세요`를 제대로 낸다(`CommandPalette.tsx:93-94`). 팔레트의 추가 실패 역시 `catch { setBusy(false); return }`로 무음이다(`CommandPalette.tsx:71`).
- **근거**: `frontend/src/pages/Watchlist.tsx:21-36`, `frontend/src/components/CommandPalette.tsx:63-76`
- **부수 증상**: 추가에 성공해도 `POST /api/refresh?symbol=`이 실패하면 시그널 행이 생기지 않고, 대시보드는 시그널 없는 티커를 `continue`로 건너뛴다(`backend/app/service.py:284-285`). 워치리스트 표는 `dash.signals.filter(s => s.in_watchlist)`로 그리므로(`Watchlist.tsx:75`) **방금 추가한 종목이 목록에 나타나지 않는다.** 사용자는 추가에 실패한 줄 알고 같은 종목을 반복 추가한다.
- **수정 방향**: 두 함수에 catch + 인라인 에러 메시지. 목록은 `signals`가 아니라 워치리스트 원장을 기준으로 그리고, 시그널이 아직 없는 행은 `"가격 수집 중 — 새로고침"` 상태로 표시한다(추가된 사실 자체는 즉시 보여야 한다).

## 7. 잘 된 점 (3개)

1. **통계적 한계를 UI가 직접 방어한다.** 비중첩 에피소드 기준 표준오차, `min_episodes` 미만 수치 은닉, "검증 불가(시간이 지나도 채워지지 않음)"와 "표본 부족"의 구분, "한 번도 발생하지 않은 등급" 명시(`BacktestTable.tsx:28-42, 66-69`). 개인용 도구에서 보기 드문 수준이고, 사용자가 표본 6개짜리 평균을 사실로 착각하는 것을 구조적으로 막는다.
2. **판단→실행 마찰 제거가 일관되게 적용됐다.** 상세에서 바로 매매 기록(`TradeDialog`), 현재가 프리필, 계산된 손절가 원클릭 룰 등록(`TickerDetail.tsx:138-144`), 심볼 자동완성(`SymbolInput.tsx`). 기록 마찰이 복기 기능을 자기잠식하던 1차 리뷰 지적이 제대로 닫혔다.
3. **경고 색을 시세 색에서 분리했다.** `--warn` amber를 별도 축으로 두어 "갱신 실패"가 "주가 하락"과 섞이지 않는다(`theme.css:6-8`). 코드 주석에 그 판단 근거가 남아 있는 것도 유지보수 관점에서 좋다.
