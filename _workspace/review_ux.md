평가 질문: **"이 애플리케이션이 실제 투자 의사결정에 도움되는 도구인가?"**
방법: 코드 정적 분석 (frontend/src 전체 + backend/app/api.py + service/portfolio 보조 확인). **실행 미검증** — 브라우저 렌더링·반응형은 확인하지 않았다.
일자: 2026-08-15

## 1. 한 줄 판정

**조건부 Yes.** 판단 재료(등급·지표별 근거·ATR 손절가·백테스트 초과수익·계좌 리스크)는 개인용 도구 기준 이례적으로 충실하지만, 그 재료가 **"지금 이 종목을 얼마나 살까/팔까"라는 행동으로 이어지는 경로가 화면상 끊겨 있고**(대시보드 시그널 행에 보유·평단 정보 부재, 상세→매매 입력 동선 없음), 포트폴리오 화면의 에러가 사용자에게 전혀 보이지 않으며 예수금 입력이 기존 값을 0으로 날릴 수 있어 계좌 숫자 자체의 신뢰가 흔들린다.

## 3. 치명적 결함 (Blocker)

### B1. 예수금 저장이 기존 값을 0으로 초기화한다 — 총자산·포지션 사이징 붕괴

- **증상**: 포트폴리오 진입 시 예수금 input은 항상 빈 문자열로 시작한다(`frontend/src/pages/Portfolio.tsx:59-60`). 달러 예수금만 수정하려고 KRW 칸을 비운 채 저장을 누르면 `Number('') === 0` → `!(0 >= 0)` 이 false라 검증을 통과하고(`Portfolio.tsx:63-64`), `PUT /api/cash` 가 `amount: 0` 으로 전송된다. 백엔드는 그대로 덮어쓴다(`backend/app/api.py:134`).
- **근거**: `Portfolio.tsx:59-73`, `backend/app/api.py:131-137`
- **사용자 영향**: 원화 예수금이 소리 없이 0이 된다. 총자산(평가액+예수금)이 줄고, 그것을 분모로 쓰는 **1% 리스크 포지션 사이징 수량이 과소 계산**된다(`TickerDetail.tsx:180-188`, `PLAN.md:14-18`). 사용자는 잘못된 수량을 근거로 진입한다. 되돌릴 이력도 없다.
- **수정 방향**: (1) 화면 로드 시 `pf.totals.cash_krw` / `cash_usd` 를 input에 프리필한다. (2) 빈 문자열은 "변경 없음"으로 취급 — USD가 이미 `amount_usd: null = 유지` 규약(`api.py:128`)을 쓰므로 KRW도 동일하게 optional 로 바꾼다. (3) 값이 절반 이상 줄면 확인 프롬프트.

### B2. 포트폴리오 로딩 실패가 사용자에게 보이지 않는다

- **증상**: `load()` 의 catch 는 `setMsg(String(e))` 만 하고 `pf` 는 null로 남는다(`Portfolio.tsx:75-78`). null이면 즉시 스켈레톤을 return 하므로(`Portfolio.tsx:93-101`) `msg` 를 렌더하는 코드(`Portfolio.tsx:291`)에 도달하지 못한다.
- **근거**: `frontend/src/pages/Portfolio.tsx:75-101`, `:291`
- **사용자 영향**: 백엔드가 죽었을 때 화면이 **영원히 로딩 중처럼** 보인다. 사용자는 "느린 건가?" 하고 기다리다가 낡은 기억으로 판단한다. 재시도 수단도 없다.
- **수정 방향**: 에러 상태를 `pf` 와 분리해 스켈레톤 return 앞에서 먼저 검사하고, "다시 시도" 버튼을 함께 낸다. Dashboard(`Dashboard.tsx:29`)에도 재시도 버튼이 없으므로 같이 적용.

### B3. 대시보드 시그널 테이블이 "내 보유 종목"과 연결되지 않는다

- **증상**: 시그널 행에 노출되는 보유 정보는 11px 회색 "보유" 텍스트 하나뿐이다(`Dashboard.tsx:104`). 평단가·수익률·보유수량이 없다. 타입 정의상 아예 전달되지 않는다(`frontend/src/types.ts:7-15` — `SignalRow` 에 avg_price/pnl 없음). 정렬은 `-abs(swing_score)` 이므로(`backend/app/service.py:213`) 보유 종목이 워치리스트 종목 아래로 밀린다.
- **근거**: `Dashboard.tsx:97-129`, `types.ts:7-15`, `backend/app/service.py:213`
- **사용자 영향**: 개인 투자자가 장중에 가장 먼저 확인해야 할 **"내가 들고 있는 것 중 매도 신호가 뜬 종목"** 이 첫 화면에서 눈에 띄지 않는다. 워치리스트가 20종목이면 보유 3종목은 스크롤 아래다. 앱의 핵심 사용 시나리오가 화면 우선순위에 반영되지 않았다.
- **수정 방향**: 시그널 테이블을 "보유"/"관심" 두 섹션으로 분리하거나 보유 우선 정렬. 보유 행에는 평단 대비 수익률과 손절가 대비 위치를 함께 노출한다.

### B4. 판단에서 실행까지의 동선이 끊긴다 (종목 상세 → 매매 기록)

- **증상**: TickerDetail 어디에도 매매 입력이 없다(`TickerDetail.tsx:108-284`). 매매 입력은 포트폴리오 페이지 최하단에 있고(`Portfolio.tsx:273-290`), 심볼을 **자유 텍스트로 다시 타이핑**해야 한다(`Portfolio.tsx:276`, placeholder `"심볼 (예: 005930, AAPL, KRW-BTC)"`). 오타 시 백엔드가 400 `"unknown symbol — 워치리스트에 먼저 추가하세요"` 를 반환한다(`api.py:103`). 자동완성·드롭다운 없음.
- **근거**: `TickerDetail.tsx` 전체(매매 UI 부재), `Portfolio.tsx:273-290`, `api.py:98-112`
- **사용자 영향**: "상세에서 강력매수 확인 → 실제 매수 → 기록" 이 탭 이동 + 심볼 재입력 + 4필드 입력이다. 기록 마찰이 크면 기록을 건너뛰고, 그러면 평단·실현손익·진입 등급별 성과(`Portfolio.tsx:231-248`) 같은 이 앱의 차별 기능이 전부 무의미해진다. **입력 마찰이 앱의 핵심 가치를 자기잠식한다.**
- **수정 방향**: TickerDetail 헤더에 "매수/매도 기록" 버튼 → 심볼·현재가·오늘 날짜가 프리필된 모달. 포트폴리오 입력 폼의 심볼 필드는 CommandPalette와 같은 자동완성으로 교체(`CommandPalette.tsx:48-61` 로직 재사용 가능).

### B5. 데이터 신선도가 사실상 관리되지 않는다

- **증상**: 프론트는 마운트 시 1회만 fetch 한다(`Dashboard.tsx:20`). 폴링·focus refetch 없음. 백엔드 자동 갱신은 `REFRESH_INTERVAL` 주기 백그라운드 루프(`backend/app/main.py:47-58`)이므로, 탭을 열어둔 화면은 갱신 사실을 모른다. 표시되는 갱신 시각은 `datetime.now().isoformat(timespec="seconds")` 원문(`backend/app/service.py:55`)을 그대로 출력(`Dashboard.tsx:84-85`) — `2026-08-15T09:12:03` 형태.
- **근거**: `Dashboard.tsx:18-20`, `:84-85`, `backend/app/main.py:47-58`, `service.py:55`
- **사용자 영향**: 어제 열어둔 탭의 가격·시그널을 오늘 것으로 착각할 수 있다. ISO 타임스탬프는 "몇 분 전인가"를 즉시 알려주지 않아 신선도 판단에 인지 비용이 든다.
- **수정 방향**: 상대시간("12분 전") 표기 + 임계(예: 2시간/장중 30분) 초과 시 시각적 경고(색·아이콘). `visibilitychange`/`focus` 리페치 추가. TickerDetail·Portfolio에도 새로고침 버튼 노출(현재 대시보드에만 존재, `Dashboard.tsx:86`).

## 5. 잘 된 점 (3개)

1. **백테스트 한계 고지가 정직하다.** 표본 기간·표본 수·왕복 비용 차감·벤치마크 기준·"인접일 표본 중첩(자기상관)으로 실제 독립 표본은 더 적음"까지 한 줄에 담았다(`TickerDetail.tsx:193-196`). 개인용 도구에서 보기 드문 수준의 자기 검증 표기다.
2. **시그널이 블랙박스가 아니다.** 지표별 점수와 한국어 근거를 표로 전개하고(`TickerDetail.tsx:144-160`), 대시보드에서도 방향·강도가 반영된 칩으로 요약한다(`Dashboard.tsx:106-117`, `theme.css:84-95`). 등급 숫자만 던지지 않는다.
3. **"진입 등급별 실현 성과" 는 이 앱만의 학습 루프다.** 체결 시점 등급을 스냅샷하고(`api.py:108-111`) 등급별 승률·평균 수익률을 분리 집계해 "시그널을 따른 매매 vs 아닌 매매"를 비교하게 한다(`Portfolio.tsx:231-248`). 시그널 앱이 아니라 **자기 복기 도구**로 만드는 핵심 기능이다.

## 6. 미확인 항목

- **실행 미검증.** 앱을 띄우지 않았다. 실제 렌더링, 애니메이션 체감, 차트 상호작용은 확인 못 했다.
- **반응형 실측.** 모바일/태블릿에서의 실제 붕괴 여부는 코드상 위험(P2-4)만 지적했을 뿐 측정하지 않았다.
- **성능.** 대시보드가 `/api/dashboard` 단일 호출이고 CommandPalette도 열 때마다 같은 엔드포인트를 다시 호출한다(`CommandPalette.tsx:39`). 종목 수가 많을 때의 응답 시간·체감 지연은 미측정.
- **텔레그램 알림 UX.** 발송 경로는 README·PLAN에 기술되어 있으나(`README.md:32`, `PLAN.md:38-40`) 프론트에 발송 상태·성공 여부를 보여주는 UI가 있는지는 `frontend/src` 에서 발견하지 못했다 — 부재로 보이나 "미확인"으로 둔다.
- **지표 계산·시그널 로직의 타당성.** 담당 밖(`trader-mentor` 영역). 본 리뷰는 UI가 그 결과를 어떻게 전달하는지만 다뤘다.
